# 网页好友聊天

管理台的“好友聊天”页面用于查看 QQ 官方机器人的单聊联系人和本地聊天记录，并从网页发送文本消息。

## 能力边界

QQ 官方机器人 OpenAPI 当前没有提供“拉取机器人全部好友”的接口。联系人列表不是 QQ 好友列表的全量镜像，而是后端根据实际收到的事件逐步建立：

- `C2C_MESSAGE_CREATE`：收到用户单聊，保存联系人和消息。
- `FRIEND_ADD`：用户添加机器人好友。
- `FRIEND_DEL`：用户删除机器人好友。
- `C2C_MSG_REJECT`：用户关闭机器人主动消息。
- `C2C_MSG_RECEIVE`：用户恢复机器人主动消息。

需要在 QQ 管理端开通这些事件，并保证回调地址正常接收事件。事件配置页中的勾选只用于本地核对，不能代替 QQ 管理端授权。

## 发送逻辑

网页发送文本消息时：

1. 如果联系人最近 55 分钟内向机器人发送过消息，优先携带该 `msg_id` 做被动回复。
2. 如果 QQ 返回回复凭证过期，则自动改用主动消息重试。
3. 没有可用 `msg_id` 时直接使用主动消息。
4. 用户删除好友、关闭主动消息、触发频控或内容审核时，QQ 可能拒绝发送；失败原因会记录在本地聊天历史中。

## 数据存储

聊天数据保存在 Docker 数据卷中的 `/app/data/chat.db`：

- `chat_contacts`：按机器人和 `user_openid` 保存联系人、关系状态、未读数和最近消息。
- `chat_messages`：保存收到、发送和好友关系事件。
- 每个机器人最多保留最近 10,000 条聊天记录，旧记录会自动清理。

`user_openid` 只在对应机器人范围内有效，不能跨机器人复用。

## 安全

聊天页面可以查看用户消息并代表机器人发送消息。当前管理台部署前必须增加登录、反向代理访问控制或内网限制，不能直接暴露到公网。
